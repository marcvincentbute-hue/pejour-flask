# Design decisions — Flask/PostgreSQL edition

Student: 241-01057. No D1/D2 computation is required after the November 16 announcement. Stack flexibility was reported as allowed by the instructor on November 15, 2026. Keep your approved proposal and record the stack change with your own course evidence. The application is still Pejour; its four system fields remain unchanged; security limits now follow the class-wide announcement.

1. **Password hashing.** Argon2id uses 65,536 KiB memory, 3 iterations and one lane, with a fresh random salt generated by argon2-cffi. Verification reads algorithm settings from the encoded hash. Passwords, lowercase security answers and OTPs all use this helper. The settings make offline guessing more expensive, but require benchmarking on a deployment server. Existing PHP Argon2id encoded hashes can be verified without learning the original password.
2. **Strength.** Weak means fewer than 8 or more than 64 characters, any whitespace, or fewer than three of uppercase, lowercase, digits and symbols. Otherwise Strong requires at least 14 characters and all four groups; remaining accepted passwords are Medium. Both browser and server check the rules. This classroom rule is explainable feedback, not a guarantee that an apparently complex password is unguessable.
3. **Security answers.** Answers are lowercased before hashing so matching is case-insensitive. They are never displayed again, so reversible storage is unnecessary. Because answers can be guessed or discovered, they authorize only the next recovery step; email OTP is still required.
4. **CAPTCHA failures.** Failed login/recovery CAPTCHAs count toward IP blocking, but do not increment a victim account's password counter. Incorrect passwords, recovery answers and login OTPs share the account counter. Every challenge is consumed on an attempt; rendering the form requests a new noisy six-character Pillow image. Browser-side checking is only a convenience.
5. **Sessions and Back.** A random opaque cookie indexes hashed token keys in PostgreSQL; authentication data is never in browser storage or a signed readable cookie. The token rotates after full login. Cookies use HttpOnly/SameSite=Lax and Secure when HTTPS is configured. Protected routes check account version and 900-second inactivity on every request. GET polling does not extend activity; genuine user actions send CSRF-protected POST heartbeats. The UI warns at 60 seconds remaining. No-store headers and a pageshow reload supplement server checks; JavaScript cannot revoke an already downloaded screenshot.
6. **Reset authorization.** Only a correct answer followed by a reset-purpose OTP creates a five-minute server-side reset grant. It binds ID and account version. Password change locks the account, checks current and last three hashes, increments version and consumes the grant. Older authenticated sessions and pending login/reset flows then fail their version checks. There are no login links or reset authorization secrets in URLs.
7. **Log integrity.** Runtime code only inserts/selects activity_log. Setup creates tables as the administrator and grants the application role SELECT/INSERT on that table without UPDATE/DELETE/TRUNCATE; a database trigger also rejects mutations. The schema owner remains privileged and must be protected. Journal deletion removes a private entry, not audit history. Dashboard filters and monitor are read-only with respect to activity events.
8. **Scheduling.** In Windows Task Scheduler, create a task whose program is the full path to `.venv\Scripts\python.exe`, arguments `"C:\full\path\pejour-flask\manage.py" monitor`, and Start in is the project folder. Repeat every 15 minutes, select 'Do not start a new instance', and run as your own unprivileged account. The task is not installed automatically by this ZIP. The monitor uses a unique pattern/target/PHT-date constraint, so repeated scans do not duplicate daily flags. Database UTC timestamps convert explicitly to Philippine time; a 5-OTP rolling window includes exactly 600 seconds. Detection scans 24 hours; IP enforcement uses 10 minutes.
9. **JavaScript visibility.** Static JavaScript must reach the browser and is publicly readable. Directory listings and private Python files/configuration are not served. Clean Flask routes replace physical PHP URLs. No secret or final authorization decision belongs in JS; parameterized SQL, CSRF, DB session/role/version/owner checks provide protection.
10. **Hashing and encryption.** Hashes are one-way comparisons; AES-256-GCM is reversible because the owner must read their journal. Each encryption uses a fresh 12-byte nonce and a 16-byte authentication tag. AAD binds owner, entry ID and field; copying ciphertext to another field fails authentication. Private intention, title and body are encrypted; dates/moods remain readable metadata. This is encryption at rest, not end-to-end encryption: a server operator holding both key and database can decrypt.
11. **Extension exception.** The handout's specific Jr., Sr. and Roman numeral options override its general name restrictions for this field. 'Other' accepts only I, II, III, IV, IX or X and preserves the supplied case. Normal first/middle/family names retain Title Case, letter-only, spacing and repeated-letter rules.
12. **Resend accounting and mail.** OTP rows explicitly distinguish initial deliveries from actual resends. Three resends per account/purpose/15 minutes are allowed; every send has a 60-second cooldown. New successful delivery cancels old codes. SMTP failure leaves the previous code active. SMTP uses Python's standard smtplib with certificate-verified STARTTLS instead of PHPMailer, following the allowed stack change. Mail is synchronous, so a slow mail server can delay the request; production would benefit from a transactional outbox/worker.
13. **Concurrency and database.** PostgreSQL bind parameters protect all runtime values. Advisory transaction locks serialize session, IP, username, OTP and journal updates across workers. Locks are acquired in a consistent order within each flow. Atomic account/version checks prevent replay. Application startup never automatically drops tables or creates sample users. PostgreSQL functional unique indexes make username/email uniqueness case-insensitive. PostgreSQL utility DDL in the CLI setup uses psycopg Identifier/Literal quoting because utility statements do not support bind parameters for role identifiers/passwords.
